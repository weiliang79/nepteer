# Windows 11 Step 2 telemetry checklist

Step 1: all eight smoke tests **passed, as reported by the user** before Step 2. Step 2/v0.2.0-alpha native battery/device verification: **pending**. CI does not establish Steam Deck hardware correctness.

Record branch/commit, workflow/artifact URL, Windows version, Deck LCD model, display scaling and WebView2 version. Do not include serials, UUIDs or other unique hardware identifiers in screenshots/reports. Have a keyboard available; native controller input is not implemented.

1. Download `nepteer-windows-x86_64-<commit>` from a successful `feat/windows-telemetry` Desktop CI run (see HANDOFF.md). Extract the archive. Confirm Microsoft Edge WebView2 is already installed. Run the current-user NSIS installer as a standard user, or launch the extracted `nepteer.exe`. No Visual Studio, added driver or elevation is required. Record unsigned publisher/SmartScreen behavior without disabling OS security; stop on unexpected UAC.
2. Start with Automatic provider mode (the default after every restart). Confirm LIVE WINDOWS, source Windows and actual manufacturer/model or explicit Unknown. A Deck model name must not turn into a verified LCD/OLED claim. App identity should not be hard-coded to Steam Deck on another Windows PC.
3. Compare the displayed battery percentage with Windows Settings/taskbar around the same time; allow small timing differences. Confirm values are within 0–100 and zero is not treated as unavailable. Check charging while plugged in, then safely unplug and manually Refresh snapshot to observe discharging. No background polling is expected. At full charge, AC-online/noncharging/100% is interpreted as full; an indeterminate state remains unknown.
4. Confirm CPU temperature, GPU temperature and fan RPM are all Unavailable in live mode. No controls, hardware changes, overlay, input mapping or service should appear.
5. If possible, repeat on a Windows device without a battery: show No system battery and unavailable percentage, never 0%. Unknown/failed API readings must remain unavailable with Windows source and relevant diagnostics. WMI failure must not replace successful battery values with mock readings. Synthetic tests cover failures that cannot safely be induced on hardware; do not disable Windows services or alter firmware to force them.
6. Open Settings → Telemetry provider → Mock samples (development). Confirm MOCK DATA, simulated manufacturer/model, 78%, 54°C and 2800 RPM sample values. Return to Automatic and confirm LIVE WINDOWS returns. Close/reopen after mock selection: it must start Automatic/live again. Theme and temperature units should persist independently across restart.
7. Refresh repeatedly with normal intervals. Confirm loading, one request at a time, updated retrieval time, no stale data following request failure, and usable retry. Partial failure diagnostics may coexist with valid battery data. No serial, hostname or user identity should appear. The app does not produce persistent telemetry logs.
8. Recheck navigation/planned pages, touch/Tab/Shift+Tab/Enter/Space, native select keyboard controls, scrolling and resizing at 1280×800 and a narrow window. Standard close must terminate the process. Uninstall as the same user if installed; confirm no helper, service or driver remains. No hardware restoration is required because there were no writes.

## Troubleshooting and evidence

- Blank/no launch: verify WebView2, x86_64 artifact and standard-user installation. Capture relevant Event Viewer → Windows Logs → Application errors with timestamp/faulting module; redact identifiers. Do not install sensor drivers as a workaround.
- Battery unavailable: report the visible status/diagnostic and whether Windows itself reports a battery. A numeric Windows API error is safe to include. Unknown does not mean zero. No command or setting bypasses permissions.
- Manufacturer/model unavailable: report the app's fixed device diagnostic. Local WMI or firmware may lack these fields. Do not paste complete WMI dumps or serial/UUID output; no privileged query is needed.
- Source/transport error: use Refresh snapshot/Try again. An ordinary browser cannot invoke Rust; use the native app. On a developer build machine, `pnpm dev` captures terminal errors. Native WMI requests are synchronous on a worker; a stalled provider may delay completion and has no cancellation deadline in this milestone.
- Release builds do not include a console/log plugin. For a debug build, use `pnpm --filter @nepteer/desktop tauri build --debug --no-bundle` on a correctly prepared Windows machine. CI build logs are downloadable from the linked run.
- Report expected versus observed behavior, run/artifact/commit and reproduction steps. Mark each item pass/fail/not tested. Existing externally configured controller-as-pointer behavior may be observed, but Nepteer does not supply controller mappings.
