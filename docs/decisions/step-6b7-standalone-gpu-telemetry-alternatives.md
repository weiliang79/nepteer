# Step 6B.7 — Standalone GPU telemetry alternative paths

Research date: 2026-11-28. Branch: `research/standalone-gpu-telemetry-alternatives`.
Decision: **B — Best candidate identified, clearance incomplete.** Retain unavailable production GPU temperature. No implementation or physical execution is authorized.

## 1. Executive summary

The **MIT-only ADLX Rust consumer remains the best specified technical candidate**, because it already supplies the raw temperature/support/current-metrics declarations and documents GPU die-edge semantics. Removing SDK headers from normal builds removes a particular root-licensed build activity; it does not establish that the original consumer and installed-runtime use are outside the root agreement. Step 6B.6 Decision B therefore stands. No new authoritative permission was found that clears public implementation or executable distribution. [A1–A3]

Two new findings narrow the alternatives. Official ADL headers carry substantive MIT grants, but its accompanying SDK EULA also restricts source publication and requires downstream terms for Distributed Software; the relationship is unresolved. ADL is not an established licensing escape. Microsoft documents **DXCore `AdapterTemperatureCelsius`**, a materially distinct application contract with physical-adapter input and state-support discovery. However, the reviewed official documentation/header does not establish the temperature output's binary type/size, edge-versus-hotspot meaning, freshness or this driver's support. Neither alternative presently justifies a probe. [B1–B6, W1–W5]

**End the open-ended sensor research loop. Recommend one next milestone: Step 6C — Battery telemetry resilience design.** Deliver a bounded design and acceptance contract for preventing optional WMI identity acquisition from withholding already acquired battery data, without claiming that a timeout cancels native work. This addresses an existing repository limitation independently of AMD clearance. This is a future proposal, not permission to change production code now. GPU work resumes only on specific new authoritative evidence, not another general survey.

### ADL licensing and distribution

The three public include files (`adl_sdk.h`, `adl_structures.h`, `adl_defines.h`) each contain an actual MIT license grant, not just metadata. That supports using/copying their declarations and retaining notices, including compiled uses. It does not grant rights to every HTML document, sample or runtime DLL. [B2]

The accompanying five-page **ADL SDK EULA** is materially restrictive: §§2–3 define Distributed Software incorporating SDK portions and grant object-code distribution for the AMD purpose; §4 requires downstream Schedule B-like terms and notices; §5(e–g) restricts certain source licensing/publication/transfers; Schedule A allows header/example incorporation only as object code and excludes documentation redistribution. Unlike the ADLX §7 finding, this reviewed agreement supplies no comparably explicit component-local exception resolving the MIT-header relationship. [B3]

Recognize the MIT file grants and the conflicting/overlapping contractual text together. Do not conclude the EULA cancels MIT, or that MIT silently clears the full SDK/runtime consumer. An independently written loader using those headers still needs a scoped applicability determination before the intended public source/binary release. No public implementation or ADL DLL redistribution is cleared. ADL is therefore **equal or worse in unresolved licensing**, with fewer verified sensor/lifecycle advantages than the existing ADLX research.

## 11. Sensor semantics and freshness

ADLX gives the strongest reviewed semantic contract: average GPU die-edge temperature as a double in °C, distinct hotspot/intake getters, explicit support and current-metrics acquisition. Its timestamp is documented as acquisition milliseconds from system epoch, but caller clock correspondence and field-level freshness remain unresolved. [A2, 6B.6]

ADL OD5/OD6 millidegrees, OD N selector output, PMLog edge °C and DXCore Celsius must each follow their own contract. Do not reuse conversions, sentinel policies or edge labels across APIs. Scalar ADL/DXCore getters provide no verified per-sample time in the reviewed contract; PMLog session timestamps are not a validated one-shot scalar freshness solution. D3DKMT's main-adapter deci-Celsius quantity remains a rejected candidate on target.

Any future admission must separately establish API status, initialized output, explicit support where available, unambiguous GPU/physical index, numeric validity and measurement meaning. No universal zero/sentinel/range rule is invented. Freshness unresolved is an honest experimental qualifier and a production blocker. Retrieval time or a fast returning call cannot establish fresh silicon data.

## 12. Lifecycle and failure handling

ADLX's MIT helper requests **1.5.0.124**, while the pinned SDK is **2.0.0.125**; it performs bare-name loading and does not expose adequate teardown results. Do not adopt it unchanged. Follow the [6B.6 ownership map](step-6b6-adlx-rust-licensing-clearance.md#15-reference-ownership-and-cleanup): runtime-owned system is not caller-Released; acquired list/GPU/service/support/metrics references must be released before termination and unload. Fixed default initialization version, partial/failed initialization and failed termination/unload contracts remain gates. [A2]

ADL2 creates a client context using a caller-supplied allocation callback. Returned allocated outputs require matching deallocation; the callback must remain valid and cannot unwind through FFI. Official create documentation requires caller serialization and warns that the library is not guaranteed thread-safe. Destroy documentation's broader thread-safety wording does not override that warning. A single owner would serialize all calls, free owned outputs, destroy context, then unload only when safe. Partial creation, destroy failure, callback reentrancy and native stalls need explicit contracts. PMLog adds device/session/shared-pointer teardown and is not selected. [B5]

DXCore has conventional counted COM objects and adapter invalidation/removal rather than vendor session termination. Release all acquired references; never call after DLL unload. It still has unknown temperature-specific output/error semantics and blocking behavior. No callbacks/notifications, renderer access to native pointers or generic method dispatcher are proposed.

For every native candidate: unsupported, absent runtime, denied access, failed support check, invalid/null output, ambiguous identity, rejected measurement and uncertain cleanup must remain distinct. A synchronous call has no established hard timeout/cancellation here. Budget checks can skip later work after return; they cannot safely abandon the call, unload live code or justify a replacement worker. No retries, repeated queries or elevated fallback. Failure means unavailable, never fabricated telemetry.

## 14. Selected decision

**Decision B — Best candidate identified, clearance incomplete.** ADLX remains the strongest technical candidate for the desired edge metric, not a provider cleared to implement or ship. The header-free consumer reduces one source of licensing complexity but supplies no new complete-consumer permission. ADL is not demonstrably better; DXCore is a real documented lead with a specific unsafe-to-guess gap, not a cleared alternative. Decision A and C would overstate the evidence. Decision D would obscure ADLX's concrete documented path by treating unknowns as proof of impossibility.

The information limit for desk research has been reached for clearing ADLX distribution: no amount of loader rewriting or immutable dependency pinning settles contractual applicability.
