# Read-only safety boundary

Step 5A adds candidate report interpretation and simulated transitions to opt-in native HID observation to the completed read-only telemetry and QAM foundation. `get_telemetry` remains the shared system telemetry command; four fixed QAM commands manage only Nepteer windows and five main-only commands coordinate controller diagnostics. It reads `GetSystemPowerStatus` and the two non-unique manufacturer/model fields of local `Win32_ComputerSystem`. There are no hardware writes, drivers, privileged helpers, game hooks, input injection, HID feature reports, game overlays/injection, shell execution or Steam Deck Tools dependencies. Nepteer does not install a service; WMI uses Windows' existing infrastructure.

Windows selects live reads by default. Mock mode requires deliberate Settings selection and is labeled MOCK DATA, with simulated device labels and sample values. It resets to Automatic at restart. API or WMI failure never selects mock. Null/unknown/error/no-battery are distinct from valid zero. Native CPU/GPU temperatures and fan RPM remain unsupported. Provider capabilities describe implemented read paths, not hardware detection or a successful current reading.

The only WMI query is `SELECT Manufacturer, Model FROM Win32_ComputerSystem`. No unique hardware identifiers, serials, UUIDs, hostnames or user identities are requested. Device/battery readings are not persisted or logged by application code. Arbitrary WMI error text is discarded; diagnostics use fixed text and numeric Windows power API errors. LCD/OLED identification remains unverified. No privileged namespace, remote connection or WMI write/method API is used. WMI connections stay on their request worker.

There is no background system-telemetry timer, subscription or subprocess polling. A dashboard startup request, QAM open, deliberate refresh or visible-panel provider change reads a snapshot. Hidden QAM startup does not read telemetry. The UI disables refresh/provider changes while a request is pending. A stalled OS/WMI query can delay a snapshot; the synchronous WMI library has no cancellation/deadline and runs off the UI thread. No claim of real-time sensing or OS accuracy is made. Battery charge state is interpreted conservatively as documented in ARCHITECTURE.md.

The Windows installer remains per-user, unsigned, and skips WebView2 installation. The application/test manifest explicitly requests `asInvoker` and `uiAccess=false`; CI extracts/checks the built executable. An existing supported Microsoft WebView2 runtime is required. Do not bypass UAC, signing, SmartScreen or antivirus. Stop manual testing if unexpected elevation occurs.

No Steam Deck Tools source was copied, translated or bundled. Future sensors and any write-oriented controls require independent research, explicit scope approval, and hardware validation. No such controls are part of v0.5.0-alpha.2.

QAM is an ordinary separate topmost window, not injected graphics. The official shortcut plugin uses supported OS hotkey APIs, not low-level keyboard hooks. Native scope is label-specific; QAM can only read telemetry, query its status, hide and listen for native events. No remote origins, filesystem or shell grants are added. CSP is unchanged. Frontend mode selection is rejected outside main.

Windows focus restoration retains only an opaque window handle in process memory. No application titles, paths or process metadata are read, persisted or logged. The handle is checked for validity/visibility before a single activation attempt. Foreground restrictions are respected; no input synthesis, repeated forcing, input-thread attachment, Secure Desktop/UAC bypass or anti-cheat interaction is permitted. A click outside QAM hides it without restoring focus over the user's chosen target. Exclusive-fullscreen games and other desktops/Spaces may prevent useful overlay/focus behavior; no compatibility guarantee is made. Anti-cheat-protected games are excluded from initial testing.

QAM starts hidden, its close action hides, and main close exits the process. There is no tray resident process, autostart, new background service or helper. Shortcut cleanup runs on normal exit; the OS releases its registration when the process ends.

Steps 1–4 passed native CI and user-reported Windows Deck checks (14 Step 3 tests). This is historical evidence; Step 5A framing and physical button verification remain pending. Pure coordinator/mock-runtime/jsdom tests do not establish actual OS activation, touch or fullscreen behavior.

QAM navigation is explicitly restricted in its native builder to the local bundled entry page (or the exact configured Vite origin during development). Remote origins, other local pages and non-app URL schemes are rejected; this does not broaden CSP.

## Neptune diagnostics boundary

Discovery is manual; monitoring is disabled by default and requires Start Monitoring after selecting a vendor-defined candidate. Only Valve candidate VID/PID 0x28DE/0x1205 collections are considered. Candidate metadata is not proof of a Neptune-compatible protocol or permission to take ownership. Virtual Xbox controllers, ordinary keyboards/mice and unknown usages are not read targets. Standard user access may be denied, busy, opened but silent, disconnected or unsupported; no fallback elevates, takes exclusive access, disables Steam Input, replaces drivers or chooses simulated data.

Metadata queries use desired access zero. Input handles use GENERIC_READ with shared read/write permission (sharing permits other programs; it does not request write access). Only ReadFile obtains input. No output/feature report, control transfer, buffer configuration, rumble, LED or firmware operation is exposed. Serial APIs and instance properties are never queried. Paths are private in-memory open tokens, not IPC IDs. Product/manufacturer descriptions are bounded, sanitized non-unique strings. Errors expose fixed explanations/numeric codes without formatting OS/device path objects. No raw report bytes or identifying paths are logged, persisted or emitted to the frontend. Only bounded, session-local simulated transition history reaches the main diagnostics UI; no history is persisted.

A safe candidate parser and pure transition detector are implemented. Every physical controller control remains explicitly unavailable even when matching reports arrive; only deliberate simulation emits states/transitions. Report length does not establish protocol compatibility. No observed input is forwarded to Windows, another application or QAM. Native cancellation/handle cleanup runs on the worker; normal shutdown waits for cancellation completion without blocking the UI event loop. Windows drivers must complete canceled requests before their buffers can safely be freed. No promise of a hard shutdown deadline is made for a broken OS driver.

Monitoring stops on explicit Stop, rescan, normal page departure, five-minute native expiry or process shutdown. Unexpected page failure is bounded by the native deadline. There is one worker, no auto-reconnect or background service, and events are aggregated. Steam Input coexistence and passive report availability must be measured on Windows hardware. Do not terminate Steam, disable its devices, change drivers, unplug internal hardware or bypass security to obtain reports. See WINDOWS_TESTING.md. QAM permissions and CSP are unchanged; diagnostics are restricted to the main local window. No Steam Deck Tools source was consulted or reused.

Step 5A keeps published candidates, observed physical framing and physical control verification separate. It cannot promote evidence based on fixtures, CI, VID/PID, a length match or header match. No physical allowlist or user-controlled promotion toggle exists; native states are null and native transitions empty. All parsed button bytes stay private. Synthetic state is explicitly labeled, never a failed-read fallback. Malformed/unsupported content never generates releases or other events. Stop/failure/disconnect/expiry remove active state/history. The in-memory recent list is capped at 32 with no persistence, and frontend events retain the existing aggregation rate and main-only scope. Proposed future local correlation tests must be explicit, bounded, memory-only and produce safe aggregate results, not raw exports or background recording. Step 5A.1 now implements only that separate bounded opt-in evidence probe. The separately reviewed Step 5B opt-in bit-50 path below is the only authorized controller QAM action; probe/diagnostic events do not operate it.

## Step 5A.1 evidence probe

Only a manually selected native vendor collection with descriptor length 65, an active observed zero-prefixed candidate stream, a nominated published control and explicit consent can start. The same worker/handle performs all analysis. Preparation/idle/five timed cycles/final observation use Rust monotonic time, with <=30s, no auto-retry and immediate Abort. Stop/rescan/interface or owner change, disconnect/read error/session expiry and shutdown cannot leave a probe active. Session generations, expected tokens and exact-token Abort reject stale asynchronous commands. No new device ownership or permissions reach QAM.

The result is observed candidate-bit correlation pending independent review, never proof of physical meaning. Existing framing_verified/physical_buttons_verified remain false, ButtonVerified is never set, physical states stay null and native event history empty. Incompatible framing terminates the probe without a positive result. Sparse/unstable/ambiguous timing and idle false positives are inconclusive. Other known/unknown candidate-word changes are aggregate edge counts, not raw masks or a label that every noise change is mapping failure.

The private word is used only for bounded comparison, with no raw packet history, logs, exports, disk state, remote telemetry or analytics. Completed raw buffers are cleared promptly and private comparison state cleared on termination. At most one safe aggregate result is retained in memory and may be deliberately copied by the user. It excludes paths/serials/scan IDs/session tokens, has no free-text environment fields and includes only build, numeric interface metadata, format/control, manual tool labels, outcome/timing/counts. The clipboard operation copies this whitelist only and sends nothing remotely. Changing mode labels changes no Steam/Steam Deck Tools/Lizard Mode/HidHide behavior.

User evidence from Steam Deck Tools Desktop mode supports trying the exact 65-byte stream, not universal compatibility or verified mappings. Separate Steam client/Input status was not confirmed. Do not uninstall/disable tools, elevate, install drivers, configure firmware or take exclusive access to obtain a better result. Independent reviewer approval and repeated physical evidence are still required before any future mapping enablement; no promotion API or controller QAM action is implemented.

## Step 5B reviewed Quick Access route

User-supplied physical evidence supports only the narrow bit-50 QAM route on LCD/Windows 11, Steam Deck Tools controller Desktop mode, Steam running/Input unknown, interface 2 usage FFFF/0001 descriptor 65. It does not justify other mappings, environments or universal compatibility. A separate explicit Arm plus consent/context acknowledgment is required every application session. No default/persistent arming, automatic renewal/reconnect, service/tray helper or startup entry exists. Thirty-minute observation may continue inside the normal app while navigating/minimized; exit cancels it. The UI always offers main-app Disarm and reports last-known state if connection is lost.

The same native read-only adapter and one reader slot serve distinct diagnostic and shortcut modes; conflicts are rejected rather than taken over. Each report is checked with the existing exact65 parser. Only a stable observed released baseline and bit-50 rising edge can dispatch existing QAM Toggle; initial held/repeat/release, Steam/face bits, timeout or malformed data cannot act. Gaps invalidate the baseline; bad formats/read failures end the session. No source fallback, interface search or replacement bit guess is allowed. The normal diagnostic five-minute/probe thirty-second limits and physical-event suppression remain.

Generation/deadline tickets and a bounded dispatcher prevent unbounded raw-input tasks. Native QAM operations hold no HID reader/status lock. Disarm invalidates pending tickets immediately and waits out any already-started action before returning; delayed errors cannot cancel a newer session. Shutdown invalidates before background cleanup, then joins and safely drains overlapped reads. No freeing in-flight memory or force-killing threads. A broken OS driver/window operation may delay completion; no hard shutdown deadline or full-screen compatibility is promised.

No hardware writes/output/feature/configuration reports, exclusive access, drivers/admin, injected input, controller emulation/remapping, low-level keyboard/controller hooks, game hooks or anti-cheat interaction are added. Raw reports/words, held state and individual press history stay private and ephemeral, not IPC/logging/disk/remote telemetry. Source and safe metadata/status alone are public. No new package or permission is added to QAM; only main gets the three management commands. CSP, navigation restrictions and asInvoker/uiAccess=false/currentUser policy remain intact.

Nepteer never contacts, starts/stops or configures Steam Deck Tools, Steam, Steam Input, HidHide or Lizard Mode. Their independent ⋯ behavior can produce another overlay or conflict. Do not suppress it or terminate tools to obtain convenient input; disarm Nepteer's shortcut and record the result. Tool mode/LCD confirmations are supplied by the user, not detected by the application. No Steam Deck Tools code is consulted/copied/translated. New integration hardware tests are pending before merge; synthetic/CI tests establish logic/builds only.

### Step 5B lifecycle diagnostics

Arm diagnostics retain a single memory-only record and a separate last worker termination enum; there is no persistent log. Only fixed reasons, selection/eligibility booleans, stage/outcome, ever-opened/compatible-report flags, monitor/reader state and safe numeric interface metadata cross existing main-only IPC. Rejections neither take over a reader nor silently disarm another mode. Unexpected worker unwinding still drops/drains the original read-only handle before reporting terminal status. No cancellation, ownership, parser, deadline, cooldown, QAM focus or input behavior has been relaxed.

Copy Shortcut Diagnostic Summary is deliberate local clipboard use, not upload/export of input. It uses an explicit field whitelist and excludes OS/IPC strings, usernames, paths, serials, instance IDs, raw reports/words/masks and press history. The selected interface metadata is session context, not proof of a game-induced disconnect or detected controller-tool mode. No game/process detection, automatic reconnect, added permission, dependency or hardware command was introduced. Reproduce only in the already-tested environment; do not use protected-game hooks or modify drivers/tools to investigate.
