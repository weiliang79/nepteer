The Windows installer remains per-user, unsigned, and skips WebView2 installation. Foreground restrictions are respected; no input synthesis, repeated forcing, input-thread attachment, Secure Desktop/UAC bypass or anti-cheat interaction is permitted. Exclusive-fullscreen games and other desktops/Spaces may prevent useful overlay/focus behavior; no compatibility guarantee is made. Anti-cheat-protected games are excluded from initial testing.

## Neptune diagnostics boundary

Discovery is manual; monitoring is disabled by default and requires Start Monitoring after selecting a vendor-defined candidate. Only Valve candidate VID/PID 0x28DE/0x1205 collections are considered. Candidate metadata is not proof of a Neptune-compatible protocol or permission to take ownership. Virtual Xbox controllers, ordinary keyboards/mice and unknown usages are not read targets. Standard user access may be denied, busy, opened but silent, disconnected or unsupported; no fallback elevates, takes exclusive access, disables Steam Input, replaces drivers or chooses simulated data.

Metadata queries use desired access zero. Input handles use GENERIC_READ with shared read/write permission (sharing permits other programs; it does not request write access). Only ReadFile obtains input. No output/feature report, control transfer, buffer configuration, rumble, LED or firmware operation is exposed. Serial APIs and instance properties are never queried. Paths are private in-memory open tokens, not IPC IDs. Product/manufacturer descriptions are bounded, sanitized non-unique strings. Errors expose fixed explanations/numeric codes without formatting OS/device path objects. No raw report bytes or identifying paths are logged, persisted or emitted to the frontend. Only bounded, session-local simulated transition history reaches the main diagnostics UI; no history is persisted.

A safe candidate parser and pure transition detector are implemented. Every physical controller control remains explicitly unavailable even when matching reports arrive; only deliberate simulation emits states/transitions. Report length does not establish protocol compatibility. No observed input is forwarded to Windows, another application or QAM. Native cancellation/handle cleanup runs on the worker; normal shutdown waits for cancellation completion without blocking the UI event loop. Windows drivers must complete canceled requests before their buffers can safely be freed. No promise of a hard shutdown deadline is made for a broken OS driver.

Monitoring stops on explicit Stop, rescan, normal page departure, five-minute native expiry or process shutdown. Unexpected page failure is bounded by the native deadline. There is one worker, no auto-reconnect or background service, and events are aggregated. Steam Input coexistence and passive report availability must be measured on Windows hardware. Do not terminate Steam, disable its devices, change drivers, unplug internal hardware or bypass security to obtain reports. See WINDOWS_TESTING.md. QAM permissions and CSP are unchanged; diagnostics are restricted to the main local window. No Steam Deck Tools source was consulted or reused.

Step 5A keeps published candidates, observed physical framing and physical control verification separate. It cannot promote evidence based on fixtures, CI, VID/PID, a length match or header match. No physical allowlist or user-controlled promotion toggle exists; native states are null and native transitions empty. All parsed button bytes stay private. Synthetic state is explicitly labeled, never a failed-read fallback. Malformed/unsupported content never generates releases or other events. Stop/failure/disconnect/expiry remove active state/history. The in-memory recent list is capped at 32 with no persistence, and frontend events retain the existing aggregation rate and main-only scope. Proposed future local correlation tests must be explicit, bounded, memory-only and produce safe aggregate results, not raw exports or background recording. Step 5A.1 now implements only that separate bounded opt-in evidence probe. The separately reviewed Step 5B opt-in bit-50 path below is the only authorized controller QAM action; probe/diagnostic events do not operate it.
