## Primary references and licensing

- [Valve vendor/product definitions](https://github.com/libsdl-org/SDL/blob/28736f296913b3f54d31cf404a82683ab2ad3a78/src/joystick/hidapi/steam/controller_constants.h#L28): candidate vendor 0x28DE and Jupiter product 0x1205. Shared IDs do not identify a collection or protocol by themselves.
- [Microsoft: obtaining HID reports](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/obtaining-hid-reports): continuous input through ReadFile, with cautions against continuously stimulating HidD_GetInputReport.
- [Microsoft: HIDP_CAPS](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidpi/ns-hidpi-_hidp_caps): descriptor input length includes a report-ID byte, zero for unnumbered reports. - [Microsoft: interpreting HID reports](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/interpreting-hid-reports): descriptor-based usage interpretation. A vendor-defined byte array does not independently establish physical button semantics.

SDL publishes the referenced files under the Zlib license, with Valve Corporation (2020/2021) and Max Maisel (2023) notices. Nepteer's parser is an original safe slice-based implementation of factual offsets/masks and a new transition model, not a mechanical translation of SDL driver logic. The supported **candidate** identifiers are `deck_v1_bare64` and `deck_v1_zero_prefixed65`. Type 0x09 is not a HID report ID; version byte 0x01 is not reported as one. Unknown prefixes/versions/types do not become a compatible variant. Recognizable truncated/oversized/incorrect-declared-length packets are malformed, not complete states. The parser never scans arbitrary offsets for an apparent header. It reads no analog coordinates, trigger values or motion data and assumes no unverified reserved-byte constants.

No partial layout, alternate report ID, BLE, Triton, other controller or arbitrary HID format is supported. Exact input size/header and little-endian interpretation are candidate rules, not evidence of compatibility. Valid zero means released for a supported simulated control; unsupported fields remain null. Repeated held states create no duplicate transitions. Initial valid state creates a baseline without historical presses.

## Evidence levels and runtime policy

1. **Candidate (Level 1):** published format facts plus synthetic tests. A native packet matching these rules increments candidate counts and shows safe identity fields, but never promotes evidence.
2. **framing_verified (Level 2):** independently observed Windows framing from the selected collection matches identity, descriptor length, actual length and invariants over repeated tests. User-reported aggregate matches are now available, but a fully reviewed framing determination is not made by this build. This would still not validate a physical control bit.
3. **button_verified (Level 3):** each specific physical control is independently correlated with repeatable press/release observations, with no unrelated transitions and simultaneous-button checks. No controls meet this level here.

The normal diagnostic decoder has no general physical allowlist or automatic promotion command. Step 5B separately permits only the reviewed, explicitly armed bit-50 QAM route below. Both hardware verification flags remain false; native button states remain unavailable and native transitions empty. Explicit simulation can decode Phase 1 candidates through the same parser with SIMULATED INPUT and per-control simulated labels. Its observations never count as physical verification. All history is memory-only, capped at 32, and cleared on stop/error/disconnect/expiry or a format/session reset. Malformed input cannot generate releases; unknown formats reset the baseline. Four-Hz summary IPC does not export raw bytes.

## Interface/report-generation uncertainties

The physical composite device can expose mouse, keyboard and vendor-defined collections. Matching VID/PID, an eligible descriptor, successful shared open and actual received input are distinct milestones. The existing native path considers confirmed vendor-defined candidate collections only; it never silently switches to a mouse/keyboard/virtual Xbox interface. Windows metadata/read access can fail or stay silent while Steam Input or another tool is running.

SDL's full driver changes reporting/device settings; Nepteer performs none of those operations. Its published rate/counter comments do not establish whether a passive Windows collection reports continuously, only on changes, or not at all. Neither counter advancement nor button interpretation is used as an invariant. Hardware tests must compare idle and one-control activity with Steam Input left enabled and report safe counts/lengths. A timeout is not a release or permission for takeover. No special reporting mode or watchdog is enabled.

## Step 5A.1 local correlation methodology

The implemented probe accepts only the observed `deck_v1_zero_prefixed65` candidate through the existing checked parser: exactly 65 bytes, zero prefix, LE body version 1, type 0x09, declared length 64, existing checked button-word location. No alternate offset search, duplicated decoder, dynamic mask rule or silent interface switch exists. Start additionally requires the explicitly selected, active native monitor, confirmed vendor-defined usage-1 metadata, descriptor length 65, a matching observed format, one of the twelve existing candidates and explicit consent. Normal simulated diagnostics remain separate; a simulated stream cannot run a physical probe.

### Fixed monotonic phases and windows

| Native relative time              | Phase / instruction                                                 | Required observations                                                                                                            |
| --------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 0–4s                              | Preparation: release all controls, rest Deck, hands off pads/sticks | At least three identical compatible words spanning >=500ms, all twelve known candidate bits released; baseline fresh at boundary |
| 4–7s                              | Idle: do not intentionally press anything                           | At least two compatible idle reports; nominated edges are false-positive diagnostics                                             |
| 7–11, 11–15, 15–19, 19–23, 23–27s | Five cycles: press 1.5s, hold 1s, release 1.5s                      | One nominated rising edge in Press, a down sample in Hold, one falling edge in Release                                           |
| 27–29s                            | Finalizing: release all controls / hands off                        | At least one fresh compatible final sample, nominated state released                                                             |
| 29s / hard 30s                    | Evaluate / deadline                                                 | Normal completion at 29s; a delayed completion reaching 30s is inconclusive, never continued                                     |

Start commits this fixed native schedule; Rust's Instant adapter and worker tick own every transition, not React timers or report counts. React displays native phases/remaining milliseconds and makes no timed Next action necessary. Windows reads remain bounded to 100ms; the worker ticks on no-report returns, and status queries can independently enforce the deadline. A fresh baseline requires no >1.5s gap at the preparation boundary. A gap anywhere in the procedure is counted once per interval and prevents a positive conclusion. These conservative fixed rules can reject a valid but sparse controller stream; the result should remain inconclusive rather than silently widening the rules.

### Exact counters

Only complete matching words are compared. The first is a baseline, not a historical edge. For each successive compatible word, XOR with the previous word identifies actual changed bits. The nominated published mask contributes rising/falling observations, never report cadence. Unchanged down samples contribute repeated held reports without another edge. The other eleven known candidate masks contribute **popcount edges**, while bits outside all twelve known masks contribute a separate aggregate popcount. No unknown mask or value is exposed. A packet counter or analog change outside the button word cannot affect these metrics. Repeated reports with another bit held do not repeatedly count that bit.

Each cycle accepts at most one rising edge in Press and one falling edge in Release after that cycle's expected press. It also needs a down sample during Hold. Missing counts are five minus accepted expected press/release counts; completed cycles require all three. All rising/falling edges are separately counted, including out-of-window observations. An idle edge increments idle transitions; every edge not eligible in its expected window also increments outside-phase edges. Presses during preparation/idle and releases during press/hold are early; other out-of-window edges are late. Additional same-direction expected-window edges increment repeated edges. These timing counters overlap by design; they are diagnostics, not independent totals to sum. Human prompt synchronization is not proof of finger timing.

Unrelated known/unknown changes are preserved as possible contamination/noise context; they do not alone force a mapping failure. Review them independently. A terminal Observed result requires stable baseline, five complete cycles, no nominated idle/outside-phase edges, no report gaps, compatible final input and final released state. It is labeled **Observed candidate-bit correlation — pending independent review**. It cannot set any verification flag or enable native states/events. An early/late/missing/ambiguous sequence, sparse reports or failed baseline is inconclusive. Incompatible/malformed framing ends the probe as error with a framing-changed flag; no positive result is possible. Abort, owner stop/rescan/disconnect/read error/expiry/shutdown ends the active session without retry. The first terminal reason is preserved.

## Native implementation retained from Step 4

Use existing windows-sys 0.61.2 (MIT OR Apache-2.0) for SetupAPI/HID metadata and overlapped ReadFile. Metadata opens request access zero; input opens request GENERIC_READ with FILE_SHARE_READ|FILE_SHARE_WRITE. Shared access does not guarantee nondisruption; retain manual Steam Input coexistence and lifecycle tests without changing drivers, disabling devices, elevation or internal hardware modifications.

## Step 5B production scope and failure policy

Only an acknowledged reviewed configuration and manually selected native cached interface may arm. Exact numeric profile and checked packet format are both required; VID/PID or a bare64 packet alone cannot authorize it. User acknowledgment is context, not automatic LCD/tool-mode detection. Native open revalidates actual usage and descriptor length in addition to IDs. There is no replacement interface, guessed bit or silent simulation fallback.

A native thirty-minute clock starts on Arm and applies to input and pending QAM tickets. Arming/WaitingReports is not yet Armed. Initial report silence over five seconds fails with a safe error. At least three actual QAM-released reports over 200ms establish a baseline. Other control bits are ignored, including Steam held. Only a later released→pressed bit-50 edge requests existing QAM Toggle; held/release/initial pressed states do nothing. A defensive 350ms interval between accepted observed presses rejects a faster press entirely, with no deferred action once cooldown elapses. This is arrival-time debounce, not a guarantee about physical finger timing if a driver buffers reports.

A no-report gap >1.5s discards the baseline and held state, not a synthetic release/toggle. Future compatible reports must establish a new released baseline. Incompatible prefix/version/type/declared or actual length closes the shortcut session; read/disconnect/access errors end it without reconnect. Disarm invalidates generation/deadline tickets before cancel/join and drains already-started QAM operations before returning. Pending actions and stale dispatch failures cannot affect a disabled or newer session. Dispatch is bounded to four pending tickets and one in-flight operation; overflow/QAM failure ends the session instead of accumulating tasks.

Diagnostics/probe and shortcut share one reader slot but distinct lifetimes. The diagnostic five-minute timer is never extended or restarted to implement the shortcut. Mode conflicts require explicit stop/disarm. An armed thirty-minute session survives navigation/minimization inside the app, never survives app exit/restart and never auto-renews. No input word, held state or press history is exposed to React. Normal diagnostic physical states remain unavailable and verification flags unchanged; only the private reviewed route can request a QAM action.

Steam Deck Tools/Steam may independently handle ⋯ and display their own UI. Nepteer makes no suppression/exclusivity promise, communicates with neither tool and changes no mode, Lizard Mode, HidHide, emulation or device configuration. Record duplicate overlays/conflicts and disarm Nepteer; do not weaken ownership/security. The 28-item Windows checklist is required for the new integration, with desktop/windowed and exclusive-fullscreen limitations separated. No anti-cheat games are in scope.
